# 試験設計

[English](../TESTING.md)

## 方針

- 実リーダーや実カートリッジを使わずに、合成した通信とROMで検証できることを基本にする。通常の試験で実機を開かない。
- 試験の成功、実カートリッジの取り込み成功、ゲームの動作は別の事実として扱い、混同しない。
- 通常の吸い出し処理を、古い試験に合わせて変えない。ハッシュ照合を省略しない。
- 実機未検証の範囲、優先順位、成功の記録条件は [HARDWARE_VALIDATION.md](HARDWARE_VALIDATION.md) を参照する。

## 構成

| 場所 | 内容 | 実行環境 |
|---|---|---|
| tests/ | 共通テスト。通信、各機種の読み出し、DB、保存、設定、管理画面、配布構成 | Python 3.9以上。PyQt6不要 |
| tests/fixtures/ | 基準通信記録（JSON） | 同上 |
| windows_tests/ | Windows GUI。模擬カートリッジとQtのオフスクリーン実行を使う | PyQt6が必要 |
| tools/diagnose_status.py | カートリッジ状態の生応答を記録する診断（実機用） | 実リーダー |

実行：

```sh
python -m unittest discover -s tests -q
python -m unittest discover -s windows_tests -q     # Windows GUI。QT_QPA_PLATFORM=offscreen
```

- MiSTerでは、一時ファイルの置き場を指定して実行する：`TMPDIR="$PWD" python3 -m unittest discover -s tests -q`。
- 通常ZIPには tests が含まれない。試験は検証用ZIPまたはソースのルートで行う。
- このソースにはCI設定を含めていない。Python 3.9 と 3.12 での共通テスト、WindowsでのGUIテストを推奨する検証環境とし、実行済みの結果とは区別する。

## 検証の観点

### 通信とトランスポート

- パケットの組み立て、応答ヘッダー、1バイトずつの分割受信、部分受信とタイムアウト、無応答、不正ヘッダー、末尾の状態応答不一致。
- 04／05の送信バイト列と、NES読み出しの通信順序。
- 状態コード（未挿入の0と255、複数挿入の254、未定義値）、3回安定の判定、抜き差し・再接続・二重取り込み防止。
- USB（CDCの制御、エンドポイントの選択、代替設定の扱い）、入力回復の上限（時間・バイト数・回数）、回復後の継続。
- 送信失敗・受信失敗の例外チェーンとエラー文言。

### 基準通信記録との比較

- 各バンク切替手順を合成バス上で実行して得た基準通信記録（fixtures）と、Pythonの読み出しアドレス・サイズ・バンク書き込み順を比較する。
- 基準記録と意図的に異なる箇所（補正した初期化、追加した保護書き込み、制限した範囲）は、差分の位置を明示して別に検証する。
- 比較に使うのは、アドレスのデコード、バンクレジスター、窓の切替を独立して模したモデル。読み出したデータが期待どおりのROMに再構成されることを確認する。

### 各機種の読み出し

- 全バンクの再構成、最大容量、境界バンク、容量の下限と上限、サブマッパー、対応外の構成が通信前に停止すること。
- 2回目の読み出し破損、PRG・CHR・全体ハッシュの不一致、DB未収録、SHA-256不一致、ヘッダー変化、カートリッジ交換、切断、キャンセル。
- 失敗した方式を無条件に別方式で再試行しないこと（許可した限定再試行は上限回数を検証）。
- 書き込みの許可アドレスと値の制限（禁止アドレス・値・型の拒否）。
- 受信データは、受信した順序とバイト値を保って保存される（MDの交換・インターリーブをしない、PCEのビット反転はDB照合で決める）。

### DB

- 形式の検証（版、必須項目、ヘッダーとサイズの整合、重複ID、競合するレコード）。
- 部分ハッシュによる候補検索、自動判定グループの条件、未対応マッパーの理由。
- 同梱DBの件数・メタデータ・対応条件を検証する。DB再生成用のツールはこのソースに含めない。

### 保存

- 一時ファイル経由の公開、既存ファイルを置換しないこと、同名・同内容の再利用、同名・別内容の別名保存、古い一時ファイルの掃除。
- Linuxのシステムコール経路（renameat2、ARM EABIの直接呼び出し、ハードリンクの代替）は模擬呼び出しで検証する。
- 保存後のファイル再照合と、別名ファイルを名前ではなく内容のハッシュで検証すること。

### 設定・環境

- 保存先とコア設定の検証（不正な値の拒否、既定の補完、優先順位）、機種ごとの保存先、環境の自動判定。
- MGLの内容とファイル名、FIFOへの起動コマンド（FIFOでない、受け手がいない、長すぎる場合）。
- 名称・ランチャー。

### 画面

- Windows GUI：接続、自動判定、候補選択、Noでの見送り、同名競合、処理中の再操作防止、キャンセル、閉じる操作、キーボードフォーカスの維持。
- MiSTer管理画面：メニューの並びと初期カーソル、候補画面、確認画面（既定No）、進捗、端末サイズによる表示の切り詰め、パッド入力のデコード。

### 配布

- 収録パターンが意図したファイルだけを選ぶこと（個人設定・ログ・ROM・ネイティブバイナリの除外）。
- manifestのSHA-256がZIP内容と一致すること。

### 環境差

- MiSTerの最小Python構成にはShift-JISのコーデックがない場合がある。コーデックを除いた模擬環境でも通ることを確認する。
- Python 3.9の構文で通ること。
