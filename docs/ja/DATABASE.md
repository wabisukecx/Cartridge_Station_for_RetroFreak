# データベース設計

[English](../DATABASE.md)

## 方針

- 同梱DBは、タイトル・サイズ・ハッシュ・ヘッダー等の**メタデータだけ**を持つ。ROMの内容は含まない。
- DBは全体ハッシュによる検証の基準であり、読み出し実装の対応範囲とは別のもの。DBに収録されていても、読み出し条件に当てはまらなければ取り込みはできない。DBの収録は、実機で読めること・ゲームが動作することを意味しない。
- JSONファイルをそのまま同梱し、起動時に読み込む。実行ファイルへの埋め込みや内容の秘匿はしない。利用者が内容を確認・差し替えできる。
- 対象はその機種向けに市販されたカートリッジ。近年の新作、復刻向け新作、ホームブリュー、ハック、翻訳改変、海賊版、未発売試作は標準DBに加えない。
- すべてのDBは `version: 1` を持ち、版が異なれば読み込みを拒否する。不正なレコードがあれば全体を拒否し、一部だけ読み込むことはしない。

## FC/NESのDB（profiles形式）

### トップレベル

| キー | 内容 |
|---|---|
| version | 1 |
| profiles | プロファイルの配列（最大10万件） |
| import_skipped | 取り込めなかったレコードと理由 |
| summary | 件数の集計 |

### プロファイル

| キー | 内容 |
|---|---|
| id | 一意のID。通常は `<raw SHA-1>-m<mapper>-s<submapper>`。重複はエラー |
| title | 表示名（240文字以内、制御文字なし）。ファイル名に使うときは安全な文字へ置換し、予約名なら `NES_<raw SHA-1>` にする |
| mapper／submapper | マッパー番号（0〜4095）と副番号（0〜15） |
| prg_size／chr_size | PRG／CHR ROMのバイト数 |
| header | 16バイトのiNES／NES 2.0ヘッダー（hex）。トレーナーなし |
| prg_sha1／chr_sha1 | PRG、CHRのSHA-1（CHRなしなら省略可） |
| raw_sha1 | PRG+CHRのSHA-1 |
| file_sha1 | ヘッダー付き完成ファイルのSHA-1（任意） |
| probes | 部分ハッシュ。first1k_sha1、last1k_sha1、halflast1k_sha1、lastprev16k_1k_sha1 のいずれか |
| prg_crc32 | PRGのCRC32（任意。CNROM-CPの解除値の選択に使う） |

- 読み込み時に、ヘッダーのマッパー・副番号・PRG／CHR容量がプロファイルの値と一致することを検証する。一致しなければ拒否する。
- 未対応のヘッダー形式（トレーナーあり、指数形式の容量、コンソール種別・拡張ビット）は読み込みで拒否または対応不可とする。

### 候補の検索（識別）

- 初期状態のPRGに対し、0x8000から1 KiBのダミー読み出し、続けて0x8000から1 KiB（先頭）、0xFC00から1 KiB（末尾）を読む。書き込みやバンク切替は行わない。
- 先頭のSHA-1を `first1k_sha1` と `lastprev16k_1k_sha1` の索引に、末尾のSHA-1を `last1k_sha1` と `halflast1k_sha1` の索引に照合し、2つの結果の和集合を候補とする（4索引の和集合）。
- 候補はあくまで部分一致であり、確定したタイトルではない。

### 対応可否の判定（support）

- ヘッダーのコンソール種別ビットや拡張フィールドがあれば、対応外。
- Mapper 0（副番号0、PRG 16／32 KiB、CHR 0／8 KiB）は対応。
- 対応済みマッパー番号のものは、マッパーごとの読み出し条件（副番号・容量の範囲）に当てはまれば対応。当てはまらなければ理由を返す。
- それ以外は「マッパー／構成は未対応」。
- 同梱DBの全プロファイルは、現在の読み出し条件に当てはまる。

### 読み込み順

1. CLIの `--db` または画面で明示したファイル
2. 個人DB（config/nes_profiles.json）
3. 標準DB（nes_profiles.reference.json）
- 個人DBは標準DBを置き換える（合成はしない）。未分類の追加カタログは自動で合成しない。

## 線形ROM系のDB（records形式）

GB／GBC、GBA、MD、PCE／SGX、SFCに共通。

| キー | 内容 |
|---|---|
| system | GB、GBC、GBA、MD、PCE、SFC のいずれか（DBごとに固定） |
| title | 正式名（拡張子付き） |
| size | ROMのバイト数 |
| sha1 | 全体SHA-1（小文字hex40桁） |
| sha256 | 全体SHA-256（任意。あれば照合で必須） |
| platform | PCE DBのみ。PCE または SGX |

- 検証：機種が一致し、サイズが整数で偶数かつ機種ごとの範囲内、SHA-1の形式が正しく、タイトルが空でないこと。同じ (サイズ, SHA-1) に異なる内容があれば競合として拒否する。SHA-256があれば形式も検証する。
- 照合は (サイズ, SHA-1) の索引で行う。一致したレコードにSHA-256があれば、データのSHA-256も一致する必要がある。不一致はDB整合性のエラーで、分類差などとして受け入れない。
- サイズの範囲：

| 機種 | 最小 | 最大 | 備考 |
|---|---|---|---|
| GB／GBC | 32 KiB | 8 MiB | 範囲外のレコードはDB生成時に除外 |
| GBA | 192バイト | 32 MiB | |
| MD | 512バイト | 16 MiB | 偶数長 |
| PCE／SGX | DBの収録サイズ | 方式ごとの上限（Linear 1 MiB、Interval 512 KiB、Sf2Dash 8.5 MiB） | |
| SFC | 32 KiB | 16 MiB | |

- 同じ容量・同じSHA-1で重複するレコードは、タイトル順で一意にする。
- GB／GBCは、ヘッダーの分類（GB／GBC）で全体照合し、一致しない場合に限り別分類で同容量・同SHA-1のレコードを調べる。別分類で全体ハッシュ（および収録されていればSHA-256）が一致したときは、「ヘッダーの分類とDBの分類が異なる」という診断で停止する。ROMの保存や別分類への自動再分類、拡張子・コアの変更は行わない。両分類に同じROMがあればヘッダー分類の一致を優先して通常どおり保存する。

## 更新の方針

- 同梱DBは配布時点で確定したデータで、リポジトリには再生成用のツールを含めない。
- FC標準DBの取り込み結果：2,148プロファイル、71種類のマッパー番号。部分ハッシュ側に結合相手がないレコード（約8,250件）、PRG／CHRの矛盾、未対応のミラーリング形式は `import_skipped` に理由つきで記録する。
- 異なる基板情報のレコードは別候補として残し、同じ部分ハッシュの衝突を無理に解消しない。

### FC標準DBの収録の考え方

- Mapper 206.1 のプロファイルは、ID・表示名・完成ファイルのハッシュを固定して保持する（固定構成の検証用）。
- CNROM-CP（Mapper 185）の解除値の選択に必要な `prg_crc32` を、該当10件だけに補う。
- 全体ハッシュしか持たない追加データ（7,058件規模）は、部分ハッシュで識別できず、市販品に限定する方針にも合わないため標準DBに含めない。
