# SFC（スーパーファミコン）読み出し設計

[English](../SYSTEM_SFC.md)

## 対象と前提

- スーパーファミコンのカートリッジ。カートリッジ状態コードは1。
- ROMだけを読む。セーブデータ、RTC、フラッシュの操作は行わない。
- SuperFX搭載カートリッジは、通常のLoROMのROM読み出しで扱う。ゲーム中のSuperFX処理はMiSTerコアが担当し、読み出しの成否とゲームの動作は別の事実として扱う。
- 専用方式のROM読み出し：SA-1・S-DD1は最大8 MiB。CX4は、ヘッダー内タイトルが許可した1タイトルのLoROM（最大2 MiB）に限る。合成バスでの確認までで、実機での成功は確認していない。
- 未対応：SPC7110、許可した1タイトル以外のCX4、SFメモリ、スーファミターボ、追加スロット。SPC7110のROM初期化はセーブRAM制御のレジスター（0x4830）の操作を含み、セーブ領域を操作しない方針では扱えないため、未対応とする。

## 通信

- 読み出しコマンドは0x07。24ビットのバイトアドレス、1回は1〜32768バイト。応答ヘッダーの後に状態要求を送り、データを受け取った後に状態コード1を確認する。
- 初期化：04(1)、2F(1)、05、05、$00:C000から16 KiBを読む。
- 終了：2F(0)、04(0)、05。
- 0x2Fのパケットは5ワードで、値は最後のワード。応答（ACK）の意味を推測して追加の検査をしない。
- ROMレジスターの書き込みは0x08。要求は5ワード `(8, 8, 1, address, 1)`、準備応答 `(0, 0)`、値1バイト、完了応答 `(0, 0)` の順。公開APIは下記のROM用アドレス・値だけを許可する。

| 方式 | 許可する書き込み | ROMの読み出し |
|---|---|---|
| SA-1 | 0x2220～0x2223にそれぞれ0～3、後半4 MiBは4～7 | 128バンクごとに切替。前半64バンクは0x008000から、後半64バンクは0x808000から64 KiB間隔 |
| S-DD1 | 0x4804～0x4807にそれぞれ0～3、後半4 MiBは4～7 | 0xC00000から32 KiB間隔。128バンクごとに窓を切替 |
| CX4（許可した1タイトル） | 0x7F52に0だけ | 通常のLoROM。安定した現ヘッダー確認後に設定し、ウォームアップとヘッダー一致を再確認 |

各レジスターの値はそのレジスターに対応する値だけを許可する（例：0x2220は0または4）。セーブRAMの有効化や任意アドレスの書き込みは公開しない。専用方式は各パスの開始時と各バンクの前に設定を行う。設計判断は下記「専用方式の設計判断」にまとめる。

## 専用方式の設計判断

- SA-1・S-DD1は、開始時とバンクごとに、上表のレジスターを決まった順に書いてから読み出す。完成ROMのヘッダーは0x7FB0で検証する。
- 書き込みはROM用のレジスターと値に個別に限定する。SA-1のセーブ書き込み許可やS-DD1のDMA制御には書かない。書き込み口の公開APIは、禁止アドレス・禁止値・型を拒否する。
- CX4は、対象タイトルに限って0x7F52=0を送る。現在のカートリッジの安定したヘッダーを確認し、選択したプロファイルと一致してから書き、その後にウォームアップとヘッダーの再確認を行う。未確認のカートリッジへ専用の書き込みは送らない。
- CX4の2 MiB上限は、この実装の保守的な制限であり、チップ全体の容量上限ではない。
- ハードウェアの判定には、DB照合後の表示名を使わず、48バイトの実ヘッダー内のタイトルを使う。DBの正式名に変わっても判定は変わらない。
- SA-1・S-DD1のヘッダーは、マップ値に加えてチップ型との組合せも制限する。
- 各パスの終了では、通常のモード終了を試みる。専用レジスターの全状態の復元や電源断は保証しない。

## 識別（ヘッダーだけ）

- 接続時はヘッダーの認識だけを行う（PCEと違い、挿入時にROM全体を読まない）。
- $00:FFB0から48バイトを2回読み、次を確認する：2回の一致、チェックサムと補数のXORがFFFF、既知のマップ値、容量コード。
- タイトルの表示にだけShift-JISを使う。コーデックがない環境ではASCII代替にし、判定用のバイト列やROMのハッシュは変えない。

### ヘッダー不正の限定再試行

- 識別時と、取り込み開始時のヘッダー再確認で、完全な48バイトを2回読んで一致したヘッダーの内容だけが不正な場合に限り、終了処理→100ms待機→再初期化を行う。
- 総試行は初回を含めて最大5回（再試行は最大4回）。画面には「Checking SFC header (2/5)」のように進捗を表示し、CLIは回数を標準エラーへ出す（JSON出力には混ぜない）。
- 再試行の対象にしないもの：通信切断、短い応答、2回のヘッダー不一致、キャンセル、カートリッジの抜去や別機種、終了処理の失敗、有効だが未対応のチップ、カートリッジの交換、ROM全体の不一致。
- 5回で回復しなければ、回数と最後の理由を示して停止する。
- 再試行は総試行5回を厳密な上限とし、不正な内容と通信失敗を区別する。

## 読み出し方式

- LoROM、HiROM、BigLoROM、LoROM+HiROM は最大4 MiB。ExHiROMは最大8 MiB。
- LoROMの最後の2バンクとHiROMの最後の4バンクは、FE／FF領域を使う。
- 2 MiBを超えるLoROMは、追加のマップ判定を行う。判定サンプルが不安定なら停止する。
- ヘッダーの容量は上限の候補として扱う。DBに収録されたサイズの境界で、全体SHA-1（収録があればSHA-256）が一致したときに容量を確定する。非2冪の容量も、DBで確定できる。

## 読み出しと検証

1. 取り込みの確認後、ヘッダーと方式を再確認する。
2. 全ROMを読み出し、DBで容量を確定する。終了処理→状態確認→再初期化→安定ヘッダーと方式の再確認を行い、同じROMを先頭からもう一度読む。2回目の前のヘッダー不正は再試行しない。
3. 2回の一致と、DBの全体ハッシュで検証する。
4. 保存後のファイルを再照合する。

## 保存

- 出力は、コピーヘッダーなしの .sfc。正式名はDBの全体照合の後に確定する。
- 同名・別内容は、既存を残して検証済みの別名で保存する。既存の同一ROMは再利用する。
- DBは3,693件（32 KiB未満または16 MiB超の10件を除く）。

## 保存先とMiSTerコア

| 環境 | 既定の保存先 | コア |
|---|---|---|
| Windows | ~/RetroFreakDumps | 自動起動しない |
| MiSTer | /media/fat/games/SNES | _Console/SNES、type=f、index=1、delay=2 |

- 保存先とコアは、設定ファイルの SFC キーで変更できる。

## CLI

- `identify-sfc`：ヘッダーを確認する（title、controller、chip、rom_size、readable、limitation を出力。保存しない）。
- `dump-sfc`：確認つきで取り込む。`--sfc-db` で別DBを指定できる。

## 検証の位置づけ

- 5つの方式のバンク読み出しを、基準通信記録と比較する。独立したアドレスデコーダーでROMを再構成し、境界バンク、初期化パケットの順序、部分受信、切断、別機種、ヘッダーの不安定、既知チップと未対応の制御、非2冪容量のDB確定、ヘッダー不正の回復と停止を合成データで検証する。
- 専用方式の検証：バンクごとに異なる合成データで8 MiB全体を2回再構成し、全書き込み順と前半／後半の境界を検査する。CX4の各パスの初期化、DB正式名への変更後も実ヘッダーで判定できること、未許可タイトルの拒否も検査する。
- 2回目の直前のヘッダー変化、不完全受信、抜去、終了失敗、キャンセルでは保存へ進まない。
- 実アダプターでの専用方式の動作と、読み出したゲームの実行は確認していない。確認していない方式を、確認済みとして表示しない。
- ゲーム動作は、読み出しの成否とは別に扱う。
