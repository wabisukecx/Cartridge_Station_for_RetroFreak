# GBA 読み出し設計

[English](../SYSTEM_GBA.md)

## 対象と前提

- ゲームボーイアドバンスのカートリッジ。GB／GBC／GBA共用スロットに挿す。カートリッジ状態コードは6。
- ROMだけを読む。SRAM、EEPROM、Flashの読み書き、RTC・GPIOの制御、特殊なバンク切替は行わない。
- 出力は .gba。DBに収録された正式名で保存する。

## 通信

- 読み出しコマンドは0x1F。アドレスはバイト単位。1回は最大32 KiBのブロック。
- 応答ヘッダーを確認した後に状態要求を送り、データと状態応答を受け取る。
- 開始は04(0)、05、200ms待機。終了は04(0)、05。

## 識別

1. 先頭2 KiBを独立して2回読み、一致を確認する。
2. 先頭192バイトの固定値（0x96）とヘッダーチェックサムを検証する。ロゴ156バイト全体の照合は行わない。ヘッダーの検証だけをROMの真贋やDB一致とは扱わない。
3. ヘッダーから得るのは、タイトル文字列、ゲームコード、版。ROM容量はヘッダーにないため、識別時の容量は「Auto (DB)」と表示する。

## 容量の確定と読み出し

1. 取り込みの確認後、最初の読み出しで、DBに収録されているサイズごとに全体SHA-1を調べ、完全に一致したところで容量と正式名を確定する。
2. 04(0)・05・200ms待機を再実行し、カートリッジ状態と完全な先頭2 KiBの受信・ヘッダー一致を確認する。確定した長さをアドレス0から再度読み出す。これは電源断ではない。
3. 2回の一致、DBのSHA-1（収録があればSHA-256）を確認してから保存する。
- 容量の判定は、1／2／4／8／16／32 MiBだけでなく、DBの全サイズ（小容量・2のべき乗でない長さを含む）で照合する。FF領域やミラーの検出だけで容量を短縮しない。
- 最大32 MiBまで読んでもDBに一致しなければ停止し、未知のROMは保存しない。
- 容量が確定するまで、進捗率は上限の32 MiBを基準にするため、2回目の開始時に表示が進む場合がある。
- DBは3,154件（192バイト〜32 MiB）。収録は、全基板の実機確認を意味しない。

## 保存先とMiSTerコア

| 環境 | 既定の保存先 | 起動 |
|---|---|---|
| Windows | ~/RetroFreakDumps | 保存フォルダーから利用 |
| MiSTer | /media/fat/games/GBA | _Console/GBA、type=f、index=1、delay=2 |

- 起動前に、コアのRBFの存在と、保存ROMの全体ハッシュを再確認する。
- GBAコアの動作にはBIOSの配置が必要になる場合があり、その配置は利用者の環境の責任とする。
- 保存先とコアは、設定ファイルの GBA キーで変更できる。

## CLI

- `identify-gba`：ヘッダーを確認する（ROMは保存しない）。出力はstate（header_only）、system、title、game_code、revision。`rom_size` が null なのは、容量が未確定という正常な表示。
- `dump-gba`：確認つきで取り込む。`--gba-db` で別DBを指定できる。

## 検証の位置づけ

- ヘッダー、通信フレーム、32 MiBの境界、小容量・非2冪長のDB照合、FF領域の保持、独立2回読み、不一致、切断、中断、保存の再利用、改変の検出、MGL、CLI、両画面の表示を合成データで検証する。
- 基準通信記録と、読み出しアドレス・サイズを比較する。
