# Windows GUI 設計

[English](../FRONTEND_WINDOWS_GUI.md)

## 位置づけ

- Windows専用のPyQt6の画面。MiSTer版は別の画面（文字メニュー）で、PyQt6を必要としない。
- 読み出し・DB判定・2回読み・ハッシュ照合・同名ファイルの保護は共通のサービス層を使い、GUIは画面の制御と表示だけを持つ。
- 画面の文言は英語。ROMの保存先を開く以外に、エミュレーターの起動やFTP転送は持たない。MiSTerのコア起動操作も含めない。
- 起動はコマンド `cart_station.py gui`、または Windows用の起動ファイル。起動時にポートを列挙するだけで、リーダーへの接続や読み出しは行わない。接続は Connect を押したときだけ。

## スレッド構成

- GUIスレッドと、リーダー専用のワーカースレッド（QThread）の2つ。USBやシリアルへの通信と、ファイルの検証はすべてワーカーで行う。
- GUIはワーカーへ「操作」を依頼する。同時に実行する操作は1つだけ（実行中は他の操作を受け付けない）。

| 操作 | 内容 |
|---|---|
| connect | サービスを生成し、最初のpollを行う |
| poll | 定期的なカートリッジ状態の確認（600ミリ秒ごと。取り込み中、確認ダイアログの表示中、終了処理中は送らない） |
| select | 候補の選択 |
| capture | 取り込み。成功時は保存パス、新規作成か既存再利用か、最新の状態を返す |
| disconnect | サービスを閉じる |

- 結果は「成功」「失敗」「進捗」の3つのシグナルで受ける。
- 失敗した場合は、サービスを閉じ、接続を切った状態に戻す。「Reader session closed — check cartridge/USB connection, then click Connect.」を表示し、利用者が Connect を押して再接続する。キャンセルの場合は「Stopped safely — click Connect to continue.」を表示する。
- 進捗のコールバックは、キャンセルの要求を確認し、安全な区切りで中止の例外を投げる。

## 画面の構成

| 領域 | 内容 |
|---|---|
| タイトル | 製品名、Windows Edition、対応機種の概要。NESにはコンバーターが必要という注記 |
| Reader & destination | 接続（ポートの選択、Refresh ports、Connect／Disconnect）、保存先（Choose folder…）、DB（Custom DB…、Use default DB） |
| 状態 | 状態の文言（カートリッジの状態、進捗の段階） |
| タイトル／詳細 | 選択中の候補のタイトルと詳細（マッパー・容量など） |
| 候補の表 | Title、Mapper、PRG、CHR、Support（GB系ではController、ROM、System、Support）。行全体を選択。複数候補のときに選ぶ |
| 進捗バー | 0〜100% |
| ボタン | Read cartridge…、Cancel reading、Open save folder |
| 結果 | 保存結果と案内 |
| Activity | 直近200行までのログ |

- 接続中は、ポートや保存先、DBの変更を無効にする（変更するには Disconnect する）。接続方法は Auto-detect またはCOMポートの指定。Direct USB は表示しない。
- ラベルはすべてプレーンテキストとして扱う（外部由来の文字列がリッチテキストとして解釈されないようにする）。

## 操作の流れ

1. 接続方法を選び、必要なら保存先と独自DBを選んで Connect を押す。
2. 接続後は定期的にカートリッジを確認し、識別と候補の表示を行う。
3. 同じ手順で読める複数候補は、全体ハッシュによる自動判定にする（「Auto-detect among N candidates」）。手動選択が必要なら、挿したタイトルを表から選ぶ。未対応の候補は理由を示し、Read cartridge を無効にする。
4. Read cartridge を押すと、タイトルと保存先を示す確認ダイアログ（既定はNo）が出る。Yes のときだけ保存用の独立2回読みを始める。PCEは自動識別時にも一度ROM全体を読み、DB照合するが、この段階では保存しない。他機種の識別ではヘッダーや部分ハッシュを読む。
5. 進捗を表示し、独立した2回の読み出しと全体ハッシュの一致の後に保存する。同名・同内容は再利用する。同名・別内容は元のファイルを残し、ハッシュつきの別名で保存する（別名のときは「既存ファイルをそのまま残した」旨を表示する）。
6. Open save folder で保存先を開く。保存先がなければ、最初のROMを保存するときに作成する旨を表示する。

### キャンセルと終了

- Cancel reading は、安全な区切りでの停止を要求する。保存の書き込みが始まっていれば完了を待つ。
- 識別中（pollとconnect）にも中止できる。
- 読み出し中にウィンドウを閉じようとすると確認し、Yes なら安全な区切りで停止して閉じる。ワーカーの終了を待ってからウィンドウを閉じる。
- 状態確認中に Disconnect が押されたときは、いまの確認が終わってから切断する。

### 候補の選択の保持

- 状態の更新で候補の表を再構築するのは、候補の集合が変わったときだけ。選択行を維持し、キーボードフォーカスを失わない。
- 状態確認中に利用者が選択を変えた場合は、保留しておき、ワーカーが空いたときに適用する。

## 保存先

- 既定の保存先は設定の機種別の保存先。機種が判定されるたびに、その機種の保存先へ切り替える。
- 利用者が Choose folder で選んだ保存先、または起動時に `--output-dir` で指定した保存先は固定で、機種による切り替えをしない。
- 取り込み計測は `runtime/last_capture_metrics.json` に記録する。

## DB

- 標準DBは自動で読み込む。実行ファイルへの埋め込みではなく、JSONとして同梱する。
- 個人DB（config/nes_profiles.json）があればそれを使う。Custom DB で選んだ外部DBは、FCに対してのみ有効。GB／GBC、GBA、MD、PCE、SFCは同梱DBを使う。
- 検索は、挿入されたカートリッジの候補の識別だけに使う。DB全体を手動検索する画面は持たない。

## 導入

- Python 3.9以上。展開したフォルダーで仮想環境を作り、`requirements-windows.txt` を導入して起動する。
- 仮想環境の作成と依存の導入は、利用者の環境で行う。exe化はしない。

## 試験

- 模擬カートリッジとQtのオフスクリーン実行で、接続、候補選択、Noでの見送り、同名競合、処理中の再操作防止、キャンセル、閉じる操作、選択とフォーカスの維持を検証する。実リーダーは開かない。
