# 実機検証の管理

[English](../HARDWARE_VALIDATION.md)

ソフトウェア試験、実カートリッジの取り込み、保存したROMのゲーム動作は別々に記録する。合成バスや基準通信記録との一致だけで「実機確認済み」としない。今回の構造整理では実リーダーを操作しておらず、実機確認の範囲は増えていない。

## 優先順位と未完了範囲

| 優先度 | 対象 | 現在の根拠と残る確認 |
|---|---|---|
| 1 | SFC SA-1・S-DD1 | 合成バスで最大8 MiBの再構成とROMマッピング書き込みを検査。実カートリッジでの成功は未確認。前半／後半の境界と2回目の再初期化を優先する |
| 1 | SFC CX4 | 許可した1タイトルのLoROM、最大2 MiBに限定。合成試験までで実機成功は未確認。現在の実ヘッダー確認、0x7F52=0、再確認の順序を検証する |
| 2 | NESのマッパー・サブマッパー別の基板 | 対応条件と明示的な未検証範囲は SYSTEM_FC_NES.md を参照。下位アドレスの専用操作、SRAM保護、バス競合、配線差のある基板を優先する。別基板の成功を流用しない |
| 3 | 各機種・各転送路とホスト | 通信の合成試験や状態応答の観測を、全ROMの取り込み成功と区別する。シリアルと直接USB、WindowsとMiSTerの結果を個別に残す |

DB収録件数や読み出し可能条件は実機での成功件数ではない。ここに個別の成功記録がない対象は、この文書から実機確認済みとは判断できない。SPC7110など、実装が拒否する方式は検証のために制限を解除しない。

## 1件の検証で記録するもの

1. 日付、ソースのコミット、ホストとOS、転送路、リーダーのbuild/product。
2. カートリッジのタイトル・地域・版、確認できる基板情報、DBプロファイルID。NESはmapper/submapper、SFCは方式・チップ・容量も記録する。
3. 使用したコマンドと設定、開始から終了までの結果。I/O記録がある場合は、その保存場所とSHA-256を添える。
4. 独立した2回の読み出し一致、DB全体ハッシュ一致、保存後の再照合の成否。容量境界や最終バンクも確認する。不一致・中断・切断は成功件数に含めない。
5. ゲーム動作を別項目として記録する。実行していなければ「未実施」、実行した場合は使用コア・版と確認範囲を残す。

記録テンプレート：

```text
日付 / ソースコミット:
ホスト / OS / 転送路:
リーダー build / product:
タイトル / 地域 / 版 / 基板:
DBプロファイルID / 方式 / 容量:
コマンド / 設定:
2回読み一致 / DB一致 / 保存後再照合:
境界・最終バンクの確認:
通信記録の場所 / SHA-256:
ゲーム動作（使用コア・版・確認範囲、または未実施）:
失敗内容 / 未確認事項:
```

成功を報告する際は、この記録に結び付く基板・ホスト・転送路の範囲を明示する。
