# GB／GBC 読み出し設計

[English](../SYSTEM_GB_GBC.md)

## 対象と前提

- ゲームボーイ、ゲームボーイカラー（GBC）のカートリッジ。リーダーのGB／GBC／GBA共用スロットに挿す。カートリッジ状態コードは5（GBとGBCで共通）。
- ROM領域だけを読む。セーブRAMの有効化・読み出し・書き込み、RTC、赤外線、カメラの撮影レジスター、EEPROM、傾きセンサー、フラッシュは操作しない。
- GBとGBCの区別はヘッダーのCGBフラグ（0x80／0xC0でGBC）で決める。出力の拡張子は .gb／.gbc。

## 識別

1. モード開始（04(1)、05、200ms待機）。
2. ヘッダー（0x100から80バイト）を2回以上読み、一致を確認する。
3. 検証する項目：ニンテンドーロゴ（48バイト）、ヘッダーチェックサム、ROMサイズコード（00〜08）、カートリッジ型。
4. 画面には、ヘッダー内のタイトル、MBC、ROM容量、GB／GBC区分を表示する。DB上の正式名は、全体ハッシュの照合後に確定する。
5. 終了処理を行う。
- ロゴやチェックサムが一致しない、またはヘッダー読み出しが不安定な場合は停止する。検証を外して取り込まない。MBCや機種を決め打ちしない。
- グローバルチェックサムだけで正式名や読み出し成功を確定しない。完成ROM全体のDBハッシュを必須にする。

## 読み出し

1. 取り込み開始時にヘッダーを再確認する。
2. 独立した2回の全ROM読み出しを行う。バンクごとにMBCレジスターを書き、ROM窓から16 KiBずつ読む（先頭バンクは固定窓の0x0000から、以降は切替窓の0x4000から）。
3. 2回の一致、ヘッダーの一致、DBのSHA-1（収録があればSHA-256）を確認する。
4. 終了処理後にヘッダーを再読み出しして、カートリッジが変わっていないことを確認する。
- 容量はヘッダーのサイズコード（32 KiBを基準に2倍ずつ）で決まり、DBのサイズと照合する。
- 失敗した方式を無条件に別方式で再試行しない。通信エラー、キャンセル、2回の不一致、ヘッダーの変化、SHA-256の不一致では別方式を試さない。

## 対応するMBC

| ヘッダーから決まる方式 | 適用範囲 | 操作するレジスター・特記事項 |
|---|---|---|
| ROMのみ（型00） | 32 KiB | バンク切替なし |
| MBC1 | 最大2 MiB | 0x2000（ROM番号）、0x4000（上位2ビット）、0x6000（モード）。32・64・96番バンクは、モード1の下位窓から読む（上位窓だと次のバンクへ読み替わるため） |
| MBC1M相当（Ex2M／Ex4M） | 最大2 MiB | 特殊配線用の読み出し。1 MiBでは、バンク内容の比較で候補を選ぶ。比較は偶然の一致で誤判定し得るため、判定結果を保存の根拠にせず、完成ROMのDB一致で確認する |
| MBC2 | 最大256 KiB | ROM番号のみ |
| MBC3 | 最大2 MiB | ROM番号のみ。RTCは操作しない |
| MBC5 | 最大8 MiB | 9ビットのROM番号（0x2000と0x3000） |
| MBC6（型0x20） | 最大1 MiB | 独立した8 KiB窓AとBを両方ROMに選択（0x2800、0x3800へ0）し、0x2000と0x3000の7ビット番号で連続する2バンクを設定して16 KiBずつ読む。RAM・フラッシュは対象外 |
| MBC7（型0x22） | 最大2 MiB | 7ビットのROM番号（0x2000）。MBC5互換の0x3000への0書き込みは行わない（ROM選択を上書きするため）。EEPROM・傾きセンサーは操作しない |
| HuC1（型0xFF） | 最大1 MiB | 6ビットのROM番号（0x2100）。0x4000はRAMバンク0の選択であり、ROM上位ビットには使わない |
| HuC3（型0xFE） | 最大2 MiB | 7ビットのROM番号。0x4000はRAM選択。RAM・RTC・赤外線にはアクセスしない |
| TAMA5（型0xFD） | 最大512 KiB | 専用の口で、0xA001=1、0xA000=番号÷16、0xA001=0、0xA000=番号%16の順に書く（上位1ビット＋下位4ビット）。任意の0xA000書き込みは公開しない。セーブ・RTC・アラームは対象外 |
| ポケットカメラ（型0xFC） | 最大1 MiB | ROM番号のみ（0x2100）。撮影・写真・カメラレジスターにはアクセスしない |

- MBC1の通常配線の32・64・96番バンクは、通常のバンク読み出しをそのまま使うと誤るため、モード1の下位窓を使う補正を入れている。
- 未対応：MMM01、GB Memoryなどのマルチカート。TAMA5の512 KiB超。MBC6の1 MiB超とフラッシュ領域。HuC1とポケットカメラの1 MiB超。
- HuC1は、ROM番号が6ビットで表現できる1 MiBまでに限る。MBC6は、バンク番号が8 KiB単位の7ビットのため64個目の16 KiBブロックで先頭へ折り返すため、1 MiBまでに限る。容量がこれを超えるヘッダーは、通信を始める前に停止する。
- バンクレジスターへの書き込み口（gb_register）は、アドレスと値を制限する。MBC6とTAMA5は専用の口を持つ。

## 照合と保存

- DBはタイトル・サイズ・SHA-1（任意でSHA-256）を持つ線形ROM系のDB（約3,455件）。サイズが範囲外のレコードは含まない。
- GB／GBCの分類は、ヘッダーで決めた分類で全体照合する。一致しなければ別分類を調べ、同容量・同SHA-1（収録があればSHA-256も）が別分類にあるときは「ヘッダーの分類とDBの分類が異なる」と表示して停止する（ROMを保存せず、再分類もしない）。例：`GB/GBC classification differs: header GBC, DB GB; no ROM saved. SHA-1: ...`
- 両分類に同じROMがある場合は、ヘッダー分類の完全一致を優先して通常どおり保存する。
- 保存は、DBの正式名で .gb／.gbc。

## 保存先とMiSTerコア

| キー | PC既定 | MiSTer既定 | コア |
|---|---|---|---|
| GB | ~/RetroFreakDumps | /media/fat/games/Gameboy | _Console/Gameboy、type=f、index=1、delay=2 |
| GBC | ~/RetroFreakDumps | /media/fat/games/GBC | 同上 |

- GBとGBCの保存先を分ける理由：ConsoleModeがGBCのROMをGameboyフォルダーでは認識せず、GBCフォルダーで認識するため。コア自体は共通のGameboyコアを使う。
- 保存先とコアは、設定ファイルの GB／GBC キーで別々に変更できる。キーがなければ上記の既定を補う。
- GUIのCustom DBはFC用で、GB／GBCは同梱DBを使う。CLIは `--gb-db` で別DBを指定できる。

## 診断

- 診断コマンド（diagnose-gb）は、GBヘッダー（0x100から80バイト）を3回読み、受信hex、ロゴの一致バイト数（/48）、チェックサム、フラグ・型・容量コード、読み出し同士の一致をJSONで表示する。リーダーの読み出しモード開始・終了は行うが、バンク書き込みや全ROMの読み出し、保存はしない。
- 付加オプション：
  - 接続開始時の04(0)を製品情報の取得前に送る比較用の指定。通常の取り込みへは自動適用しない。
  - 通信トレース（JSON Lines）の出力。環境間の送受信の比較に使う。
- 症状の切り分け：特定のカートリッジだけでヘッダーの2回読みが一致しない、またはロゴが一致しない場合は、接点・リーダーの状態・受信処理のどれかであり、診断の出力で比較する。検証を外して回避しない。

## 検証の位置づけ

- 各MBCは、バンクのデコードを独立に模した合成ROMで、全バンクの再構成、最上位バンク、2回目の破損、未知のDB、通信失敗、キャンセル、交換検出、保存後の全体検証・再利用を確認する。
- 通常ROM／MBC1などの基準通信記録と、アドレス・サイズ・書き込み順を比較する。基準記録にない補正（MBC1の32・64・96番バンク、HuC3の7ビット、MBC7の0x3000書き込み省略、MBC6・HuC1の上限）は、仕様資料に基づく独立モデルで検証する。
- 実物のカートリッジがない方式は、モデルでの検証にとどまる。
