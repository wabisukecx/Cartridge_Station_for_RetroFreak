# メガドライブ（MD）読み出し設計

[English](../SYSTEM_MD.md)

## 対象と前提

- メガドライブ／ジェネシスのカートリッジ。カートリッジ状態コードは2。
- ROMだけを読む。セーブRAM、EEPROM、Flashへのデータ書き込みは行わない。
- 書き込み（コマンド0x0E）は、ROMのマッピングレジスター0xA130F1（値0／1）と0xA130FF（値0〜23）だけ。これ以外のアドレスは公開しない。

## 通信

- 開始は04(1)、05、200ms待機。終了は04(0)、05。
- 読み出しコマンドは0x0D。アドレスはバイト単位、最大32 KiBのブロック。結果ヘッダーを確認した後に状態要求を送り、データと状態応答を受け取る。

## 識別

1. 0x100〜0x1FFを16バイトずつ読み、さらに独立した2回の一致を要求する。
2. SEGAの識別子を確認し、ROMの開始アドレス・終了アドレス（ビッグエンディアン）を解析する。
3. タイトル、シリアル、読み出し方式、容量の候補を得る。この容量はヘッダー等による候補であり、DBで確認した容量ではない。
- 16ビット交換されたSEGA識別子（ESAG等）は明示的なエラーとし、自動変換で通さない。
- タイトルのShift-JIS変換は、コーデックがない環境ではASCII代替にし、判定用のバイト列やハッシュには影響させない。

## 読み出し方式

| 方式 | 範囲・操作 | 選択 |
|---|---|---|
| None | 通常の線形ROM、最大4 MiB | 通常の自動判定 |
| SuperSf2 | 自動時5 MiB。通常領域の後に0xA130FFで512 KiB窓を切り替える。実装の上限12 MiB。終了時に0xA130F1=0、読み出し窓を0xA130FF=7に戻す | 国内タイトル識別子（32バイト）で自動判定 |
| SAndN | ロックオン構成（本体カートリッジ＋接続カートリッジ）。0x200100の追加ヘッダーを比較し、接続構成に応じて容量と切替を調整 | 国内タイトル識別子と接続側タイトルで自動判定 |
| MortalK2 | 最大4 MiB。2 MiB以降を別アドレスで読み、FFを含む応答を回数制限つきで再読み出し／2バイト単位へ切り替える。64バイト未満の端数も取りこぼさない | 自動判定には含めず、CLIで手動指定 |

- 通常は、ヘッダーのROM範囲に従い、タイトル名だけから容量を決めない。ただし、容量がヘッダーと一致しない既知の例外については、タイトルとシリアルが両方一致するときに限って容量を補正する。
- 各独立読み出しの前に、必要なマッピングを設定する。終了・中断時には解除を試みる。
- ヘッダーの欠落、範囲の不正、SEGA以外の識別子、未知のバンク制御は、未対応として停止する。DBの収録サイズに読み出し方式がないものは取り込めない。

## 読み出しと検証

1. 利用者の確認後に、全ROMをアドレス0から独立して2回読む。
2. 完全一致、ヘッダー一致、DBの全体SHA-1（収録があればSHA-256）を要求する。ROMの16ビット加算チェックサムは必須条件にしない。
3. 未知の全体ハッシュは保存しない。
- DBは1,969件（512バイト〜16 MiB、偶数長）。DBには上の方式で読めないサイズや特殊基板も含まれる。収録は対応済みを意味しない。

## 保存

- 受信したバイト列をそのまま保存する（16ビット交換、SMDインターリーブ、512バイトヘッダーの付加はしない）。拡張子は .md。正式名はDB一致後に確定する。
- 同名・別内容は、既存を残して検証済みの別名で保存する。

## 保存先とMiSTerコア

| 環境 | 既定の保存先 | コア |
|---|---|---|
| Windows | ~/RetroFreakDumps | 自動起動しない |
| MiSTer | /media/fat/games/MegaDrive | _Console/MegaDrive、type=f、index=1、delay=2 |

- 保存先とコアは、設定ファイルの MD キーで変更できる。
- MiSTerのMDコアは、ファイル拡張子による地域判定（.mdは欧州）を持つため、日本版はコアのAuto RegionをHeaderにするか日本を選ぶ。保存するROM自体の地域やバイト列は変更しない。

## CLI

- `identify-md`：ヘッダーを確認する。state、system、title、serial、controller、rom_size、readable を出力。保存しない。
- `dump-md`：確認つきで取り込む。`--md-db` で別DBを、`--controller` で方式（None、SAndN、SuperSf2、MortalK2）を手動指定できる。

## 検証の位置づけ

- 4方式のバンク読み出しを、合成バスで実行した基準通信記録と、Pythonの読み出しアドレス・サイズ・バンク書き込みを比較する。
- 基準記録と意図的に異なる箇所（MortalK2方式の端数処理、SuperSf2方式の読み出し窓の復帰）は、差分として明示して検証する。
- 特殊方式は合成試験での検証にとどまり、特殊基板の実物での動作は保証しない。
