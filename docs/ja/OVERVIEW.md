# 全体設計

[English](../OVERVIEW.md)

## 目的

- RetroFreak（レトロフリーク）付属のカートリッジアダプターをUSBリーダーとして使い、利用者が所有するカートリッジからROMを取り込み、検証し、保存する。
- 取り込んだROMはPCやスマホのエミュレーター、またはMiSTer FPGAのコアで利用する。
- 対象機種はFC/NES、GB/GBC、GBA、メガドライブ（MD）、PCエンジン（HuCard／SuperGrafx）、スーパーファミコン（SFC）の6系統。

## 用語

- 基準通信記録：各バンク切替手順を合成バス上で実行して得た通信記録（アドレス・サイズ・書き込み順）。tests/fixtures に置き、読み出し実装の比較基準とする。
- 候補：カートリッジの部分的な情報（ヘッダーや部分ハッシュ）から絞り込んだ、DB上のタイトルの候補。実物のタイトルが確定したことを意味しない。
- 全体ハッシュ：ROM全体のSHA-1（収録があればSHA-256）。タイトルと版の確定、保存の可否の基準。
- 独立2回読み：1回目のデータを再利用せず、機種別の開始状態から全ROMを2回取得し、バイト列の一致を確認すること。GBA・SFCは2回目の前にモード設定とヘッダー確認もやり直す。全機種で電源断やハードウェアリセットを行う意味ではない。機種別の保証範囲は CAPTURE_FLOW を参照。

## 設計原則

- 読み出し専用。セーブデータ・フラッシュ・EEPROM・RTC等への書き込みは行わない。カートリッジへ送る書き込みは、ROMバンクの切替・ROM読み出しの設定・RAM書き込み保護のための限定したレジスターだけ。
- 検証してから保存。独立した2回の全ROM読み出しが一致し、かつ同梱DBの全体ハッシュ（SHA-1、収録があればSHA-256）に一致したデータだけを保存する。
- 既存ファイルを壊さない。保存は一時ファイルから既存を置換しない方法で公開し、同名・同内容は再利用、同名・別内容は元のファイルを残してハッシュ付きの別名で保存する。
- 推測で進めない。ヘッダーやタイトル名だけで基板・容量・版を確定しない。不明・不一致・未対応は理由を示して停止する。
- 失敗した通信は再送しない。部分受信・不正ヘッダー・送受信例外が出た処理は継続せず、セッションを閉じて利用者が明示的に再接続する。
- ROMデータは同梱しない。同梱DBはタイトル・サイズ・ハッシュ等のメタデータだけを持つ。
- 画面と処理を分離する。読み出し・判定・保存・起動情報の生成は共通のサービス層が持ち、画面（Windows GUI、MiSTer文字メニュー）はそれを呼び出す。CLIは機種別の読み出し処理と共通の保存後検証処理を直接呼び出す。

## 対象外

- セーブデータの読み書き、フラッシュ書き込み、上記の限定したレジスター操作以外のカートリッジへの書き込み。
- CD-ROM系、SFメモリ・スーファミターボ等の周辺機器カートリッジ、SPC7110の専用操作、許可した1タイトル以外のCX4。SA-1・S-DD1と、許可した1タイトルのCX4のROM読み出しは実装済み（合成試験。実機未検証）。
- 市販カートリッジ以外（近年の新作、復刻向け新作、ホームブリュー、ハック、翻訳改変、海賊版、未発売試作）を標準DBへ追加すること。
- ゲーム一覧・ライブラリー管理。保存済みゲームの一覧と選択はMiSTerのConsoleModeが担う。
- 実行ファイル（exe）化、ソースの難読化。Pythonソースと標準DBをそのまま配布する。
- エミュレーターの自動起動、FTP転送（Windows版）。

## 動作環境

| 項目 | Windows Edition | MiSTer FPGA Edition |
|---|---|---|
| 実行基盤 | Python 3.9以上（導入は利用者環境） | MiSTer標準のPython 3.9とlibusb |
| 画面 | PyQt6のGUI | テレビ＋ゲームパッドで操作する英語の文字メニュー |
| 通信 | シリアル（COMポート）。自動検出または指定 | USB直接通信（PyUSB経由のバルク転送） |
| 依存ライブラリー | pyserial、PyUSB、PyQt6をpipで導入 | pyserial、PyUSBの純Pythonソースを同梱（vendor） |
| 既定の保存先 | ホームの RetroFreakDumps | /media/fat/games 以下の機種別フォルダー |
| ゲーム起動 | 行わない | MGLファイルとコマンドFIFOで対応コアを起動 |

- リーダーはUSB VID:PID f00d:1337。RetroFreakのカートリッジアダプターで、PC側にはシリアル（CDC ACM）として見える。
- NES（海外版ファミコン）の実物は、RetroFreakのアダプターに接続するためNESカートリッジコンバーターが必要。FCカートリッジはFCスロットへ直接挿す。処理上はFC/NESを共通の区分で扱う。
- 1台のリーダーを同時に使えるプロセスは1つ。管理画面・GUI・CLIを同時に動かさない。

## レイヤー構成

| 層 | モジュール | 役割 |
|---|---|---|
| 入口 | cart_station.py | srcを検索パスへ加えてCLIを起動する唯一の入口 |
| CLI | cart_station_cli | サブコマンド（list、probe、gui、manager、identify-*／dump-*等） |
| 画面 | cart_station_windows、cart_station_manager | PyQt6 GUIとMiSTer文字メニュー。どちらもサービス層だけを呼ぶ |
| サービス | cart_station_service | 接続、挿入判定、候補選択、取り込み、照合、保存、起動情報の生成 |
| 表示整形 | cart_station_presentation | 機種ごとの候補の列・詳細表示 |
| 機種別読み出し | cart_station_nes_core／nes_mappers／nes_registers／nes_db、gb、gba、md、pce、sfc | ヘッダー認識、バンク走査、ROMレジスターの検証、DB照合 |
| 共通DB | cart_station_rom_db | 線形ROM系（GB/GBA/MD/PCE/SFC）の全体ハッシュ照合 |
| 保存 | cart_station_storage | 一時ファイル経由の公開、競合時の別名 |
| 通信 | cart_station_transport、cart_station_protocol | シリアル／USBの転送路、パケット、応答検証、アダプター操作 |
| 設定・環境 | cart_station_paths、environment、branding | 設置場所、設定ファイル解決、PC／MiSTer判定、機種別保存先、名称 |
| 計測 | cart_station_metrics | 取り込み時間と通信量の記録 |

- 読み出しの依存の向きは「画面 → サービス → 機種別読み出し → アダプター → 転送路」。CLIはサービスの保存後検証処理と機種別読み出しを呼び、サービスとCLIは共通の保存処理を使う。プロトコル層はUIやCLIをimportしない。
- サービスは1つのワーカーが転送路・候補・ファイル検証を所有する。画面側は専用スレッド（Windows）またはスレッドプール（MiSTer）から1度に1操作だけ依頼する。

## 取り込みの全体手順

1. 接続：転送路を開き、製品情報（build／product）を取得する。
2. 挿入判定：カートリッジ状態を繰り返し取得し、同じ値が3回続いたとき安定とみなす。
3. 識別：機種ごとに、ヘッダー読み出しまたは部分ハッシュで候補を作る。画面にタイトル・基板・容量・対応可否を表示する。
4. 選択：候補が1件なら自動で選ぶ。同じ手順で読める複数候補は、読み出し後の全体ハッシュで決める。それ以外は利用者が選ぶ。
5. 確認：利用者の確認（既定はNo）を得てから読み出しを始める。挿入しただけでは全体を読まない（PCEは例外で、挿入時にDB照合のため一度全体を読む）。
6. 読み出し：独立した2回の読み出しを行う。
7. 検証：2回の一致、ヘッダー、DBの全体ハッシュを確認する。
8. 保存：検証済みデータだけを保存し、保存後のファイルを再照合する。
9. 起動（MiSTerのみ）：保存済みROMを再照合し、MGLで対応コアとROMを指定して起動する。

## 検証の位置づけ

- ソフトウェア試験の成功、実カートリッジの取り込み成功、ゲームの動作は別の事実として扱う。DBに収録されていることは、読み出し手順が実装・確認済みであることを意味しない。
- 読み出しの対応可否は、DBの各プロファイルが現在の読み出し条件（機種・基板・容量・副番号）に当てはまるかどうかで決まる。当てはまらないものは理由を表示して取り込みを無効にする。
